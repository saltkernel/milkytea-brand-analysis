# 奶茶品牌图鉴 v2

> **9 大品牌 · 200+ 产品 · 多维数据洞察**
>
> 纯 HTML+CSS+JS 多页站，ECharts 可视化，无构建工具，零框架依赖

**🌐 在线访问**：<https://saltkernel.github.io/milkytea-brand-analysis/>

**💻 本地直开**：双击 `index.html` 即可运行，无需本地服务器，也无需 `--allow-file-access-from-files` 浏览器参数（数据层已内置 file:// 降级加载方案）。

## 三、数据层架构

### 3.1 数据来源

`data/milkyTea.json` — 200+ 条产品记录，字段：

| 字段 | 说明 | 示例 |
|------|------|------|
| `品牌` | 品牌名 | 蜜雪冰城 / 喜茶 |
| `饮品名称` | 产品名 | 茉莉奶绿 |
| `总价/元` | 单杯价格 | 12 |
| `容量/ml` | 容量 | 500 |
| `总热量/kcal` | 单杯总热量 | 320 |
| `基底液` | 基底液类型 | 鲜奶 / 纯茶 / 燕麦奶 |
| `顶料` | 顶部配料 | 芝士奶盖 / 奶油顶 / 无顶料 |
| `茶底类型` | 茶底种类 | 红茶 / 绿茶 / 乌龙茶 |
| `是否含默认小料` | 含小料标记 | 是 / 否 |
| `单位价格 元/100ml` | 标准化价格 | 2.40 |
| `单位热量 kcal/100ml` | 标准化热量 | 48.5 |

### 3.2 MT 数据层（js/data.js）

单例 IIFE 闭包，提供全局对象 `MT`：

```javascript
// 初始化（异步 Promise）
MT.init()              // → Promise，返回原始数据数组
MT.ready(callback)     // 兼容旧版回调

// 品牌
MT.getBrands()         // 品牌名数组（按产品数降序）
MT.getBrandTotals()    // {品牌: 产品数}
MT.colorForBrand(b)    // 返回品牌色 hex
MT.brandPalette        // 14 种大地色系
MT.teaColorMap         // 茶底颜色映射

// 计算
MT.KPI()               // 汇总统计 {totalProducts, brandCount, avgUnitPrice, avgUnitHeat, mostExpensive, lowestCal}
MT.filterValid()       // 过滤 #DIV/0! 和无效数据
MT.costPerformance(item) // 性价比 = 容量ml / 总价元
```

### 3.3 双环境数据加载策略

浏览器禁止 `file://` 页面通过 fetch 读取本地文件（CORS 策略），因此数据层按运行环境自动选择加载方式：

| 环境 | 加载方式 |
|------|----------|
| `http(s)`（GitHub Pages 等线上部署） | `fetch('data/milkyTea.json')` |
| `file:`（本地双击 HTML 直开） | 动态插入 `<script>` 加载 `data/milkyTea.data.js`（数据以 `window.MILK_TEA_DATA` 全局变量内嵌） |

> 若更新了 `milkyTea.json`，需重新生成内嵌版本：
> ```bash
> node -e "const fs=require('fs');const j=fs.readFileSync('data/milkyTea.json','utf8');JSON.parse(j);fs.writeFileSync('data/milkyTea.data.js','window.MILK_TEA_DATA = '+j.trim()+';')"
> ```

## 五、论据 → 结论

### 5.1 核心论据（数据实证）

| # | 论据 | 数据来源 | 关键数值 |
|---|------|----------|----------|
| ① | 产品覆盖充分 | `milkyTea.json` | 9 品牌 × 200+ 产品 |
| ② | 数据清洗严格 | `MT.filterValid()` | 排除 #DIV/0!、热量≤0、非数值行 |
| ③ | 统计标注明确 | 热力图 / 箱线图 | n<3 虚线框、n<5 散点替代箱体 |
| ④ | 价格带分层显著 | 散点图 / 箱线图 | 低价带 < 2 元 → 中价带 2~3 元 → 高价带 > 3 元/100ml |
| ⑤ | 小料对价格和热量均有系统性拉升 | 小料对比柱状图 | 含小料均价高 0.3~0.8 元/100ml，热量高 5~15 kcal/100ml |
| ⑥ | 热量密度差异大 | 热力图 | 全脂奶+芝士奶盖组合热量最高，纯茶+无顶料热量最低 |
| ⑦ | 品牌茶底策略分化 | 堆叠柱状图 | 平价品牌绿茶/红茶主导，高端品牌乌龙茶/花茶/抹茶占比更高 |
| ⑧ | 健康评分可量化 | 健康指南 | Top 20 产品得分差距达 25 分 |

### 5.2 核心结论

**🔑 定价逻辑**
> **价格与热量无强线性相关**。高价≠高热量，定价主要受品牌溢价和原料成本驱动。
> 全品牌分为三级价格带：蜜雪冰城等 < 2 元/100ml → 中价带 2~3 元 → 喜茶/奈雪 > 3 元/100ml。

**🔑 小料经济学**
> **小料价格溢价幅度大于热量增幅**。含小料产品单位价格高 0.3~0.8 元，热量高 5~15 kcal。小料对品牌利润的贡献率高于对消费者热量负担的增加率——小料是典型的"利润杠杆"。

**🔑 热量真相**
> **一杯 450ml 奶茶 ≈ 1.8~2.5 碗米饭**（116kcal/碗）。行业均热量 40~60 kcal/100ml，最高可达 80+ kcal/100ml。芝士奶盖+全脂牛奶是热量密度最高的组合，纯茶+无顶料是最低热量组合。

**🔑 配方策略**
> **红茶和绿茶是全品牌通用底层茶底**，几乎所有品牌都有相当比例的红茶和绿茶产品。高端品牌（喜茶、奈雪）茶底更多元：乌龙茶、花茶、抹茶占比更高，体现"茶饮专业化"定位。

**🔑 减卡路径**
> **选纯茶底 + 去芝士奶盖 + 选小杯 = 热量可降低 50%+**。消费者在不牺牲喝茶体验的前提下，可通过三步操作大幅降低热量摄入。

**🔑 健康决策**
> **无糖/三分糖版本可比全糖少 80~150 kcal**。健康评分系统将多维度因素量化为单一分数，为消费者提供可操作的选饮品依据。

## 六、技术亮点

1. **零框架依赖**：纯 HTML+CSS+JS，无 npm、无 webpack、无 jQuery，开箱即用
2. **双环境数据加载**：线上走 Fetch API + Promise 单例，本地 file:// 自动降级加载内嵌数据，无需任何浏览器启动参数
3. **旭日图钻取联动**：ECharts sunburst 三层点击钻取（品牌→基底液→茶底），联动 5 张图表同步筛选 + 标题更新
4. **统计严谨性**：每张图表标注样本量阈值（n<3 虚线、n<5 散点），避免小样本误导结论
5. **滚动渐入动画**：IntersectionObserver + CSS transition，图表卡片、section 标题逐个淡入
6. **渐进式响应**：flexbox/grid 自适应 + 768px 断点，移动端保留全部功能
7. **开屏只播一次**：sessionStorage 标记，关闭标签页后重置——兼顾首次体验感与回访效率
